# Reliability audit — October 5, 2026

## Findings fixed

1. **Lease expiry during lock contention.** The finalisation query checked the expiry in its WHERE predicate before obtaining a contested row lock. A paused worker could record success after its lease had expired. A new integration test reproduced this with independent database connections: it returned true where false was required. Finalisation now locks the matching delivery/token, then checks the current database time. Recovery retains the attempt as interrupted.
2. **Stale browser requests on navigation.** Manual and automatic refreshes could outlive their delivery page. Requests now share a per-delivery in-flight guard and abort on navigation, preventing old responses from replacing the selected delivery. The regression test failed before the fix and passes afterward.
3. **Static asset security headers.** Asset-first routing bypassed the Worker branch that set browser headers. Actual local HTML responses lacked CSP, nosniff and referrer policy. The exported `_headers` file now applies them on the actual asset path, covered by browser-suite response assertions. The static Next.js export still requires inline-script permission; this is not a claim of a nonce-based CSP.

## Additional checks

- Real browser journeys cover all five receiver behaviours, replay lineage, verified signatures, timeout results and actual 429 spacing.
- A browser test lets an ingestion commit, then discards its response. Resubmitting uses the same key and yields exactly one persisted delivery.
- Repeated worker interruption consumes the five-attempt budget and reaches final failure.
- Browser fault tests cover unavailable data, manual recovery and the three-minute polling cutoff. These use intercepted responses and are distinct from the real delivery journeys.
- Formatting, lint, type checks, 30 unit tests, 27 PostgreSQL integration tests, eight browser tests, static build and Worker bundles pass locally.
- Desktop and 390-pixel mobile rendering were inspected; no horizontal overflow or browser exceptions were found.
- A stale, long-running local Wrangler process stopped responding during rebuilding. Restarting it restored the preview; final browser verification ran against the fresh process. Hosted runtime behaviour is not inferred from this local restart.

## Presentation changes

The homepage now explains an order notification surviving a shipping-service outage. It links to source/tests/architecture. Delayed queue work is labelled explicitly; the README no longer implies a strict 30-minute recovery ceiling when bounded batches or outages can add delay. The [reviewer walkthrough](reviewer-walkthrough.md) maps demo actions to implementation evidence.

## Hosted release status

At the time of this local audit, the hosted deployment had not yet been verified. The later October 5 deployment and hosted smoke checks are recorded in the [hosted verification report](hosted-demo.md), including receiver exposure, session isolation and delivery/replay behaviour.

Local regression results and hosted checks are separate evidence. The free demo remains bounded by provider capacity and application quotas; the hosted report records measured CPU limits and availability constraints. Neither report guarantees defect-free software or unlimited free availability.
